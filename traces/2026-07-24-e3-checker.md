# e3-checker — deterministic narration fence built (E3 gate)

- **Queue item:** ROADMAP E3 — Narration (AI, fenced). This trace covers
  the DETERMINISTIC half (the checker + gate); the narrator (model call) is
  deferred to the voice decision.
- **Why:** E3's gate is the checker, not the prose: "a fabricated-claim
  fixture is caught by the checker." The checker is the AI/deterministic
  boundary enforcement — it can and should exist before any model call, so
  the narrator is never trusted un-fenced.
- **What was built:** `dispatch/narration.py` (pure, no model calls):
  `real_ids` (every collected fact id), `cited_ids` (parses `[F0007]` /
  grouped `[F0007, F0012]`), `check` (reports two distinct failure classes —
  fabricated ids and uncited claim-sentences — plus a coverage note of
  uncited real ids). `bin/check-narration` CLI: exit 0 safe / 1 rejected /
  2 bad input. Three gate fixtures over the existing fixture-day.json:
  good (passes), fabricated ([F9999] caught), uncited (ungrounded sentence
  caught).
- **Evidence consulted:** charter §Domain ("narrator receives ONLY the
  FACTS file; the checker rejects uncited or nonexistent-id claims"); ROADMAP
  E3 gate; the fact-id scheme in dispatch/facts.py (`F%04d`).
- **Design decisions (recorded as decision 8):** citation syntax `[Fxxxx]`
  inline, grouped allowed; a claim-sentence is a `.?!`-terminated span,
  headings + code fences exempt; every claim-sentence needs >=1 citation;
  full fact coverage is NOT required (uncited real ids are a note, not a
  failure). dispatch-facts.1 is FROZEN as-is — E3 is its first consumer and
  the post-leak-fix shape is clean, so no `.2` bump.
- **Alternatives rejected:** a smarter "is this sentence a claim?" detector
  (undecidable deterministically; the strict every-sentence-cited rule is
  the honest deterministic reading and forces grounding); requiring the
  narration to cite every fact (would punish good editorial selection).
- **Verify:** full, exit 0; 61 unit tests (8 narration) — the narration
  fixtures run under pytest, which `./verify full` already invokes, so the
  charter's "narration-checker fixtures" gate is satisfied without a verify
  edit.
- **Open questions:** narrator voice/length (blocks the model half of E3);
  whether the narrator runs as a subagent vs an API call in this harness.
